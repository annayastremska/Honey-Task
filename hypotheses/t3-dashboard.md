# t3. Операційний дашборд для CEO

## 1. Умова
Дані завдання 2; операційний дашборд для CEO; не більше 4 блоків; Tableau; бізнес у цілому, без груп A/B тесту.

## 2. Хто і що хоче бачити (ресерч, 29.09.2026)
- **Операційний дашборд** — щоденний погляд на стан бізнесу, щоб помітити проблему й відреагувати; не аналітичний (фільтри для дослідження) і не стратегічний (роки) ([Few, типи дашбордів](https://www.sumboard.io/guides/dashboard-types)).
- **CEO читає, а не аналізує:** стан бізнесу зрозумілий за ~5 секунд; зверху — плитки з ключовими показниками, під ними — 2–4 графіки; 5–9 показників на екран ([executive dashboard practices](https://appdeck.com/blog/executive-dashboard-design-best-practices)).
- **Показники споживчого застосунку:** активні користувачі (DAU), утримання, конверсія в платника, виручка на платника (ARPPU) ([UXCam](https://uxcam.com/blog/important-mobile-app-analytics-metrics/), [Adapty](https://adapty.io/glossary/arppu/)).
- **Платформи коміксів:** гроші дає невелика частка платників (Webtoon — 4,6% читачів) за доступ до епізодів; головні показники — читачі, платники, виручка на платника ([Taddy, Webtoon business model](https://taddy.org/blog/how-does-webtoon-business-work)).

## 3. Питання CEO → блок — пропозиція, не погоджено
| Питання CEO | Блок |
|---|---|
| Як ми зараз: гроші, люди, платники? | 1. Плитки: виручка, платники, активні користувачі, нові реєстрації, конверсія в платника, виручка на платника — за останній тиждень і зміна до попереднього |
| Куди рухаємось? | 2. Динаміка по днях: виручка і активні користувачі (два окремі графіки, без двох осей) |
| Чи лишаються нові? | 3. Утримання нових: частка тих, хто повертається на 1-й і 7-й день, по тижнях реєстрації |
| Що читають? | 4. Контент: комікси за прочитаними епізодами і читачами |

- Фільтри: період; платформа (країна / ОС).
- ⚠ 14–15.08.2022 — оплат у даних нема: позначити на графіку як пропуск даних, не як падіння.
- ⚠ Останній день даних — 25.08.2022; «зараз» на дашборді = 25.08.2022.

## 4. Рішення Анни (29.09.2026)
- 4 блоки: ключові числа + 3 графіки; порівняння — тиждень до попереднього.
- Дані — сирі csv у Tableau; усі перетворення — calculated fields, без SQL-підготовки.

## 5. Модель даних у Tableau — пропозиція
- Зв'язки (Relationships), центр — `users`: `users.id` = `transactions.user_id`, `users.id` = `visits.user_id`, `users.id` = `reading_log.user_id`; `reading_log.comic_id` = `comics.comic_id`.
- Для утримання всередині логічної таблиці `visits` — фізичне об'єднання `visits` ⨝ `users` (inner, `user_id` = `id`): кожен візит має одного користувача, тож рядки не множаться, а день після реєстрації рахується в межах одного рядка.
- Кожен графік бере дату своєї таблиці; спільний період — через параметр «кінець періоду» (25.08.2022), а не через фільтр дати.

## 7. Пропозиція дашборда (29.09.2026) — не погоджено
1. **Ключові числа** (6 плиток: число + зміна до попереднього тижня + міні-лінія тренду): виручка, платники, активні користувачі, нові реєстрації, конверсія в платника, виручка на платника.
2. **Виручка по днях** — лінія або стовпчики; 14–15.08 позначені як пропуск даних.
3. **Активні по днях: нові і повернуті** — стос із двох кольорів; показує залежність від залучення.
4. **Утримання нових по тижнях реєстрації** — таблиця-теплокарта: рядок = тиждень реєстрації, стовпці = день 1…7, колір = частка тих, хто зайшов.
- Фільтр: платформа (країна / ОС). Контент і групи A/B не показуємо.
- **Старт A/B тесту (Анна, 29.09.2026):** на всіх графіках із віссю часу — вертикальний пунктир 01.08.2022 з підписом «старт A/B тесту частоти імейлів», навіть якщо всі користувачі показані однією лінією. Причина: зміни після 01.08 частково можуть бути ефектом тесту. У Tableau — Reference Line на осі дати, константа 01.08.2022, пунктир. У теплокарті когорт — межа між тижнями 25.07 і 01.08.
- **Графік 2 (Анна, 29.09.2026):** накопичувальна діаграма «нові + повернуті» (stacked area / bar), не воронка.
